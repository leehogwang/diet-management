# 양 추정 개선 실험 정리 — 기대값 디코딩(T=1)과 GRL + 강한 증강

- 작성 2026-11-09. 분할 `122_2_forunseen`(처음 보는 음식 23종, test 5,884장) 기준.
- **상태: 정리만 해 둔다. 파이프라인(`n296/pipeline_infer.py`)과 README 8.1 의 현재 최고 구성에는 적용하지 않았다.**
  두 방법 모두 효과의 방향은 좋지만 영양 G4 개선이 0.2~0.5%p 수준으로 작고, 음식 단위로 보면 우연과 구별되지 않는다(4절).
- 비교 기준(현재 최고, README 8.2 `r_ing`): 1인분 값 = 분류기 통과 사진은 영양 모델, Gemini 로 넘긴 사진은 Gemini 1인분(음식명 + 재료),
  양 = 양 추정 모델(CE) argmax 비율. **unseen G4 33.67**, 양 정확도 0.557. 정답 Q 를 쓰면 G4 27.93 (양으로 줄일 수 있는 여지 5.74%p).

## 1. 배경: 양 추정에서 무엇이 틀리나

처음 보는 음식에서 양 추정 모델(CE)의 오류를 나눠 보면:

| 확인 | 결과 |
|---|---|
| 같은 음식 안에서 양 순서 (Spearman, 음식 23종) | 0.83 ~ 0.97 (중앙 0.94) |
| 음식별 치우침 (예측 등급 − 정답 등급, 평균) | 갈치조림 −1.58, 미소된장국 −0.89, 크림소스스파게티 −0.82 / 시래기된장국 +0.93, 감자튀김 +0.63, 자장면 +0.60 |
| 음식별 최적 정수 이동 (상한) | 정확도 0.617 |
| 같은 음식 사진 묶음을 순위로 5등분 (진단용, 실제로는 못 씀) | 정확도 0.732, ±1 0.988 |

모델은 상대적인 양은 알지만, 처음 보는 음식의 1인분(Q4)이 어느 정도인지 기준점을 모른다.
학습 음식 44종의 생김새와 양 기준을 외워, 처음 보는 음식은 비슷하게 생긴 학습 음식의 기준을 따라가는 것으로 본다.
아래 두 방법은 각각 ① 출력 해석(디코딩)과 ② 학습 방식(음식 정체성 제거)에서 이 문제를 줄이려는 시도다.

## 2. 방법 A — 분류 확률로 비율 기대값 (T=1)

### 2.1 방법

양 추정 모델은 Q1~Q5 분류 모델이다. 지금은 확률이 가장 높은 등급의 비율을 쓴다(argmax).
기대값 디코딩은 다섯 등급 확률로 비율을 가중 평균해 **연속 비율**을 만든다.

```
argmax      : r = RATIO[argmax_k p_k]                    RATIO = [0.25, 0.5, 0.75, 1.0, 1.25]
expected_T1 : r = Σ_k softmax(logit)_k × RATIO_k          (temperature 없이, raw softmax)
최종 영양값 = 1인분 값 × r
```

- **재학습 없음.** 이미 저장된 test logits(`runs/122_2_forunseen_quantity/test_logits_pipe.npz`, 대분류 입력 `pipe_osr`)만 다시 해석한다.
- temperature 보정을 하지 않는 것이 핵심이다. val 로 맞춘 temperature(T = 2.29)를 쓰면 확률이 평평해져 기대값이 가운데(약 0.75)로 끌려가고,
  Q1 사진을 크게 과대추정한다.

### 2.2 같이 비교한 디코딩 (`src/compare_quantity_decode.py`, 재학습 없음)

| 디코딩 | G4 | A4 | 비율 MAE | 정답 Q별 상대 오차 (Q1 → Q5) |
|---|---|---|---|---|
| argmax (현재) | 33.67 | 35.01 | 0.134 | 0.32 · 0.26 · 0.23 · 0.16 · 0.10 |
| expected (T = 2.29) | 38.44 | 48.36 | 0.197 | **1.20** · 0.27 · 0.11 · 0.16 · 0.25 |
| **expected_T1** | **33.43** | 35.83 | 0.142 | 0.50 · 0.26 · 0.20 · 0.15 · 0.13 |
| median_T1 | 33.66 | 35.05 | 0.133 | 0.33 · 0.26 · 0.23 · 0.16 · 0.10 |
| median (T = 2.29) | 34.07 | 35.90 | 0.133 | 0.43 · 0.24 · 0.20 · 0.14 · 0.12 |
| min_rel (상대 오차 기대값 최소) | 42.08 | 37.87 | 0.220 | 0.28 · 0.22 · 0.16 · 0.28 · 0.42 |

### 2.3 결과

- G4 33.67 → **33.43 (−0.24%p)**. 영양소별 G: 칼로리 29.77 → 29.52, 지방 47.53 → 47.46, 단백질 31.50 → 31.14, 탄수 25.90 → 25.62, 중량 21.05 → 21.70.
- 좋아지는 곳: Q2~Q5 의 1등급 차이 오류가 연속 비율로 반쯤 상쇄된다(Q3 상대 오차 0.23 → 0.20, Q4 0.16 → 0.15).
- 나빠지는 곳: Q1(1/4 인분) 사진. 확률이 Q2 쪽으로 조금만 새도 비율이 커져 상대 오차가 0.32 → 0.50 으로 커진다. A4(사진별 상대 오차 평균)가 35.01 → 35.83 으로 나빠진 이유다.
- 음식별로는 23종 중 14종에서 나아졌다. 크게 나아진 음식: 전주비빔밥 −2.2, 소고기무국·소고기김밥 −1.8, 새우튀김 −1.4.
  크게 나빠진 음식: 갈치조림 +6.9, 미소된장국 +3.5, 해물찜 +1.8 (모두 양을 적게 보는 쪽으로 치우친 음식).
- 신뢰도 (`src/bootstrap_expected_t1.py`, paired bootstrap 2,000회):

| 재표본 단위 | G4 차이 (expected_T1 − argmax) 평균 | 95% 구간 | expected_T1 이 나은 비율 |
|---|---|---|---|
| 사진 | −0.24 | [−0.39, −0.08] | 1.00 |
| 음식 | −0.25 | [−0.71, +0.24] | 0.84 |

사진 단위로는 유의하지만, 처음 보는 음식이 바뀌면(음식 단위) 0 을 포함한다.

## 3. 방법 B — 음식 정체성 제거(GRL) + 강한 증강

### 3.1 방법

양 추정 모델의 백본 특징에서 "어떤 음식인지" 정보를 지워, 음식 종류가 아닌 단서(그릇이 채워진 정도, 쌓인 높이 등)로 양을 판단하게 만든다.

```
사진 → 강한 증강 → ConvNeXt-Tiny 백본 → 특징 f ─┬→ [f ⊕ 대분류 임베딩 64] → 양 헤드 → Q1~Q5     손실 L_Q (CE, smoothing 0.1)
                                               └→ GRL → 음식 헤드 (학습 음식 44종)              손실 L_food (CE)
전체 손실 = L_Q + L_food
```

- **GRL (gradient reversal layer):** 순전파에서는 f 를 그대로 넘기고, 역전파에서는 기울기에 −λ 를 곱한다.
  음식 헤드는 음식을 잘 맞히도록 학습되지만, 백본은 뒤집힌 기울기를 받아 음식 헤드가 음식을 **못** 맞히는 특징을 만들도록 밀린다.
- **역전 세기 일정:** `λ_p = λ × (2 / (1 + exp(−10p)) − 1)`, p = 학습 진행률(0 → 1). 초반에는 0 에 가깝게 시작해 양 학습을 먼저 안정시킨다. λ = 1.0.
- **음식 헤드:** `Linear(768 → 256) → GELU → Linear(256 → 44)`. 학습에만 쓰고 `best.pth` 에는 저장하지 않는다. **추론 구조·속도는 기존 양 추정 모델과 같다.**
- **강한 증강 (`--aug strong`):** 기존(Resize 384, 좌우 반전, RandomAffine 10°/5%, ColorJitter 0.2) 에 RandomGrayscale 0.5,
  ColorJitter 0.4/0.4/0.4/0.1, GaussianBlur(9, σ 0.5~2.0) 30% 를 더했다. 색·질감처럼 음식 종류를 드러내는 단서를 약하게 하려는 것이다.
  양 단서를 망가뜨리지 않도록 크기·위치 증강(crop, scale)은 바꾸지 않았다.
- 나머지 학습 설정은 기존 양 추정 모델과 같다: AdamW lr 1e-4 (헤드 ×10), wd 0.05, warmup 1 epoch + cosine, batch 48, drop_path 0.1,
  fp16, 최대 30 epoch, patience 6, val 정확도 최고 체크포인트, 끝나고 val 로 temperature 보정.
  val 은 학습에 없는 음식 12종이다.

실행: `src/train_quantity.py --split 122_2_forunseen --grl 1.0 --aug strong --tag _grlaug` → `src/eval_quantity_cats.py --tag _grlaug` → `src/compare_quantity_soft.py` (`run_grl.sh`).

### 3.2 학습 과정

| epoch | val 정확도 | 음식 헤드 정확도 (학습 배치) |
|---|---|---|
| 1 | 0.460 | 0.163 |
| 2 | 0.474 | 0.053 |
| 4 | 0.501 | 0.020 |
| **10 (best)** | **0.506** | 0.024 |

음식 헤드 정확도가 epoch 4 부터 0.02 안팎(44종 무작위 = 0.023)에 머물렀다. 특징에서 음식 정보가 의도대로 지워졌다.
기존 CE 모델의 best val 정확도는 0.493 (epoch 9) 이다. val 로 맞춘 temperature 는 2.35 (기존 2.29) 로, 둘 다 처음 보는 음식에서 확신도가 낮다.

### 3.3 결과 (unseen test 5,884장)

| 양 추정 모델 | Q 정확도 | 2등급 이상 틀림 | 비율 MAE | 음식별 치우침 평균 / 최대 | 순위상관 중앙 | G4 argmax | G4 expected_T1 |
|---|---|---|---|---|---|---|---|
| 기존 CE | 0.557 | 7.9% | 0.134 | 0.43 / 1.58 | 0.94 | 33.67 | 33.43 |
| 강한 증강만 (`_aug`) | 0.553 | 7.6% | 0.136 | 0.42 / 1.34 | 0.94 | 33.82 | 33.46 |
| **GRL + 강한 증강 (`_grlaug`)** | **0.589** | **4.6%** | **0.116** | **0.34 / 0.97** | 0.95 | **33.41** | **33.16** |
| 정답 Q (상한) | 1.000 | 0% | 0 | 0 / 0 | — | 27.93 | — |

- 정답 Q별 정확도 (CE → GRL + 강한 증강): Q1 0.73 → 0.75, Q2 0.52 → 0.55, Q3 0.39 → 0.43, **Q4 0.45 → 0.54**, Q5 0.69 → 0.67.
- 영양소별 G (argmax): 칼로리 29.46, 지방 47.13, 단백질 31.13, 탄수 25.91, 중량 20.38.

- 순위상관(0.94 → 0.95)은 거의 그대로이고 음식별 치우침이 줄었다. 1절에서 지목한 문제를 실제로 건드린 개선이다.
- 그러나 G4 는 0.26%p 만 줄었다. 양으로 줄일 수 있는 여지 5.74%p 의 약 5% 다. 1등급 차이 오류(약 36%)가 대부분 그대로 남았다.

  (후속 3런은 GPU 2개에 나눠 동시에 돌렸다. 속도만 느려졌고 설정은 같다.)

## 5. 판단과 남은 일

**적용하지 않는다.** 두 방법 모두 방향은 좋지만, 영양 G4 개선이 0.2~0.5%p 로 작고 음식 단위로는 우연과 구별되지 않는다. B 는 재현도 되지 않았다.

적용을 다시 검토하려면 먼저 할 것:

1. **seed 반복:** 기존 CE 와 `_grlaug` 를 seed 3개씩 학습해, 양 정확도 0.589 가 재현되는지 확인 (GPU 2개로 약 1시간).
2. **체크포인트 선택 안정화:** val 정확도 대신 val 비율 MAE 나 val G4 로 고르기, 또는 마지막 epoch 들의 가중치 평균(SWA/EMA).
3. **음식 단위 평가:** 학습 음식을 돌려 가며 빼는 K-fold 로 평가해, 23종 1회 test 의 우연을 줄이기.
4. 재현되면 A + B 를 함께 `pipeline_infer.py` 에 옵션으로 넣는다 (양 추정 체크포인트 교체 + `--quantity-ratio expected` 를 T=1 로 계산하는 옵션).
   기존 `--quantity-ratio expected` 는 temperature 를 적용한 확률을 쓰므로 그대로 쓰면 안 된다 (2.2절 expected T = 2.29, G4 38.44).
